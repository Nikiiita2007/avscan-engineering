# avscan — руководство

Учебный антивирусный сканер на **C++20** — переписанная версия `ANTIvirus.js`. Реализованы все пункты ТЗ: однопроходное сканирование, сигнатуры с условиями, разбор PE, распаковка архивов с лимитами, эвристика с подробным отчётом по баллам, нечёткие хэши, пять статусов результата, кэш.

> Это учебный проект, а не замена промышленному антивирусу. Реальных вредоносных сигнатур в базе нет — их нужно добавлять самому.

## 1. Состав архива

| Файл | Назначение |
|---|---|
| `CMakeLists.txt` | сборка (CMake ≥ 3.16) |
| `src/main.cpp` | CLI: аргументы, обход каталогов, коды возврата |
| `src/scanner.hpp/.cpp` | ядро: однопроходное чтение, SHA-256, Aho–Corasick, эвристика, статусы, кэш |
| `src/sigdb.hpp` | загрузчик базы сигнатур, шаблоны с `??`, автомат Ахо–Корасик |
| `src/pe.hpp` | разбор PE: секции, точка входа, импорты |
| `src/sha256.hpp` | потоковый SHA-256 (без внешних библиотек) |
| `src/fuzzy.hpp` | нечёткий хэш в стиле ssdeep (CTPH) и сравнение |
| `src/archive.cpp` | распаковка ZIP (zlib) и 7z/RAR (libarchive) с лимитами |
| `src/cache.hpp` | кэш результатов |
| `src/report.hpp/.cpp` | текстовый и JSON-отчёты |
| `src/selftest.*` | встроенные тесты (`--selftest`) |
| `db/signatures.db` | пример базы сигнатур |
| `tests/make_test_files.py` | генератор тестовых файлов (EICAR-zip, zip-бомба и др.) |

## 2. Сборка

Нужен компилятор с C++20: GCC ≥ 11, Clang ≥ 14 или MSVC 2019 16.11+ / 2022. Проверено на GCC 15 с флагами `-Wall -Wextra` (предупреждений нет).

### Linux / macOS

```bash
sudo apt install build-essential cmake zlib1g-dev libarchive-dev     # Debian/Ubuntu
# brew install cmake zlib libarchive                                  # macOS

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/avscan --selftest
```

### Windows (Visual Studio + vcpkg)

```powershell
vcpkg install zlib libarchive --triplet x64-windows
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
build\Release\avscan.exe --selftest
```

### Без CMake

```bash
g++ -std=c++20 -O2 -DAV_HAVE_ZLIB src/*.cpp -lz -o avscan                                   # ZIP через zlib
g++ -std=c++20 -O2 -DAV_HAVE_ZLIB -DAV_HAVE_LIBARCHIVE src/*.cpp -lz -larchive -o avscan    # + 7z/RAR
g++ -std=c++20 -O2 src/*.cpp -o avscan                                                       # без зависимостей
```

| Сборка | ZIP | 7z / RAR |
|---|---|---|
| без зависимостей | не распаковывается → Skipped | то же |
| + zlib | да | нет |
| + libarchive | да | да |

Если архив проверен не полностью, он **не** получает Clean: итог — минимум Skipped.

## 3. Быстрый старт

```bash
./avscan --selftest                          # проверка ядра
./avscan file.exe                            # один файл
./avscan -r ~/Downloads                      # каталог рекурсивно
./avscan -v suspicious.exe                   # подробный отчёт по баллам
./avscan --json -r dir > report.json         # JSON
python3 tests/make_test_files.py && ./avscan -v testfiles/*
```

Коды возврата: `0` — чисто, `1` — есть Infected, `2` — есть Suspicious, `3` — есть Error, `4` — ошибка аргументов.

База ищется в `db/signatures.db` (текущий каталог, затем рядом с exe, затем на уровень выше); иначе укажите `--db`.

## 4. Опции командной строки

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--db FILE` | `db/signatures.db` | база сигнатур |
| `-r` | выкл | рекурсивный обход каталогов |
| `-v` | выкл | подробный отчёт по каждому баллу |
| `--json` | выкл | вывод в JSON |
| `--no-cache`, `--cache FILE` | кэш вкл, `.avscan_cache.tsv` | кэш результатов |
| `--max-size MB` | 2048 | файлы больше лимита → Skipped |
| `--max-depth N` | 3 | глубина вложенных архивов |
| `--max-unpacked MB` | 1024 | суммарно распаковано за один скан |
| `--max-entry MB` | 256 | один распакованный файл |
| `--max-entries N` | 10000 | файлов во всех вложенных архивах |
| `--max-ratio N` | 1000 | распаковано / размер корневого файла |
| `--suspicious N` | 40 | порог Suspicious |
| `--infected N` | 150 | порог Infected по баллам |
| `--selftest` | | встроенные тесты |

## 5. Как устроено ядро

### 5.1 Один проход

Файл читается блоками по 64 КБ. Каждый блок сразу попадает в SHA-256, автомат Ахо–Корасик, гистограммы энтропии (общую и по секциям PE) и нечёткий хэш. Повторного чтения содержимого нет. Сигнатура на границе блоков не теряется: автомат хранит состояние между блоками, а проверка маски идёт по скользящему окну.

Два честных исключения: заголовок PE разбирается из уже прочитанного первого блока, но таблица импортов читается точечными `seek`-чтениями (несколько КБ); архивы после основного прохода открывает распаковщик.

### 5.2 Статусы

| Статус | Когда |
|---|---|
| `Clean` | файл прочитан полностью, ничего не найдено, баллы ниже порога |
| `Infected` | malware-сигнатура или хэш из базы, либо баллы ≥ `--infected` |
| `Suspicious` | баллы ≥ `--suspicious` |
| `Error` | ошибка чтения, файл не найден, прочитано не столько байт, сколько заявлено |
| `Skipped` | символическая ссылка, не обычный файл, слишком большой, архив проверен не полностью |

Ошибка чтения **никогда** не даёт `Clean`. Статус архива — худший среди вложенных объектов (Clean < Skipped < Error < Suspicious < Infected).

### 5.3 Кэш

Ключ: `абсолютный путь | размер | время изменения (нс) | версия базы`. Смена `version|...` в базе инвалидирует кэш. Error, Skipped и частично проверенные архивы не кэшируются. Из кэша берутся статус, баллы, хэши и имена детектов; для подробного отчёта используйте `--no-cache`.

## 6. База сигнатур

Текстовый файл, `#` — комментарий.

```text
version|2026.11.07-1
sig|Имя|malware|pe|60 E8 ?? ?? ?? ?? 5D 81 ED && @0x40:"PE"
sig|Имя|suspicious|script|"powershell" && "-enc"
sha256|<64 hex>|Имя.Образца
fuzzy|<blocksize:sig1:sig2>|Имя.Семейства
```

Поля `sig`: имя; класс (`malware` — сразу Infected, `suspicious` — +40 баллов); тип файла (`any`, `pe`, `elf`, `script`, `zip`, `7z`, `rar`, `jpeg`); условия.

Условия соединяются через `&&` — должны выполниться **все**. Условие — это hex-байты (пробелы необязательны, `??` — любой байт) или строка `"text"`, с необязательным префиксом `@смещение:` (десятичное или `0x..`, абсолютное от начала файла). В условии нужно минимум 2 подряд идущих точных байта: по ним строится автомат, остальное (маска, смещение) проверяется потом.

Тип определяется по содержимому, не по расширению. `pe` — это MZ **и** корректный `PE\0\0` по `e_lfanew`. Поэтому сигнатура, привязанная к `pe`, не срабатывает на JPEG, ZIP и «голых» MZ — это проверяет `--selftest`.

Хэши — SHA-256 (MD5 из `ANTIvirus.js` не поддерживается). Хэш образца показывает обычный запуск `./avscan file`.

## 7. Эвристика и подробный отчёт

Каждый признак даёт баллы, вердикт выносится по порогам. Флаг `-v` печатает **все** проверки — сработавшие и нет — с объяснением:

```text
[+25/25] PE_HIGH_ENTROPY_EXEC — Высокая энтропия исполняемой секции
         ПОЛУЧЕНО: Секции UPX1(7.97) имеют энтропию ≥ 7.2 из 8: код выглядит зашифрованным или упакованным.
[ +0/15] PE_WX_SECTION — Секция одновременно записываемая и исполняемая
         НЕ ПОЛУЧЕНО: W+X секций нет.
```

Для не-PE файлов PE-проверки сворачиваются в одну строку «НЕПРИМЕНИМО».

| ID | Баллы | Что проверяется |
|---|---|---|
| `PE_HIGH_ENTROPY_EXEC` | 25 | исполняемая секция с энтропией ≥ 7.2 |
| `PE_PACKER_SECTION` | 30 | секции UPX0/UPX1, .aspack, .themida, .vmp0, .mpress1 и др. |
| `PE_WX_SECTION` | 15 | секция и записываемая, и исполняемая |
| `PE_FEW_IMPORTS` | 15 | ≤ 5 импортируемых функций или нет таблицы импорта |
| `PE_ENTRYPOINT` | 15 | точка входа вне секций или в последней секции |
| `PE_SUSPICIOUS_APIS` | 8 / 25 | 1–2 или ≥ 3 API инъекции, кейлоггинга, загрузки |
| `PE_EMPTY_RAW_BIG_VIRTUAL` | 10 | секция пуста на диске, но ≥ 64 КБ в памяти |
| `PE_FILE_ENTROPY` | 10 | энтропия всего файла ≥ 7.0 |
| `FUZZY_FAMILY` | 30 / 60 | сходство с семейством из базы 50–79 % / ≥ 80 % |
| `SIG:<имя>` | 40 | сработала `suspicious`-сигнатура |
| `ARCHIVE_LIMIT` | 40 | превышен лимит распаковки (zip-бомба) |
| `ARCHIVE_ENCRYPTED` | 10 | в архиве зашифрованная запись, не проверена |
| `ARCHIVE_PATH_TRAVERSAL` | 20 | путь в архиве с `../` (zip-slip) |

С порогами 40 / 150 один признак вроде UPX (30) файл подозрительным не делает — нужна комбинация. Баллы и пороги подбирайте на своей выборке (баллы — в `peIndicators()` в `scanner.cpp`). Высокая энтропия нормальна для архивов, JPEG и установщиков, поэтому PE-проверки применяются только к PE.

## 8. Нечёткие хэши

`Fuzzy` — собственная реализация алгоритма в духе ssdeep (формат `blocksize:sig1:sig2`). Сравнение: общая 7-символьная подстрока + расстояние редактирования, результат 0–100. Ограничения:
- хэши **не гарантируют** побитового совпадения с утилитой `ssdeep`; сравнивайте только хэши, посчитанные avscan;
- TLSH не реализован (обычно подключается готовая библиотека); место для подключения — `FuzzyHasher` и блок «нечёткие хэши» в `Scanner::scanSource`.

Чтобы добавить семейство: просканируйте образец, возьмите строку `Fuzzy:` и добавьте в базу `fuzzy|<хэш>|Имя`.

## 9. Защита от zip-бомб

Лимиты проверяются в процессе распаковки: заявленный и фактический размер записи, общий объём, отношение к размеру корневого файла, число записей, глубина вложенности. При превышении распаковка прекращается, добавляется `ARCHIVE_LIMIT`, итог — не ниже Suspicious. Проверено: ZIP с 400 МБ нулей (~400 КБ) останавливается на лимите записи; цепочка из 6 вложенных ZIP — на глубине 3.

## 10. Что изменилось относительно ANTIvirus.js

| Было (JS) | Стало (C++20) |
|---|---|
| MD5 | SHA-256 |
| подстрока без условий, `FFD8FFE0` как «вирус» | условия, маски, смещения, привязка к типу |
| ошибка чтения → `isMalicious=false` | ошибка → `Error` |
| `Map` по пути | кэш по пути + размер + mtime + версия базы |
| отдельные проходы для сигнатур и хэша | один проход |
| самотест с JPEG-«вирусом» | тесты на ложные срабатывания, границу блоков, смещения, маски, AND-условия, упакованный PE |

## 11. Не проверено и ограничения

- Модуль libarchive (7z/RAR) написан по документации API, но в среде разработки libarchive не было: он не компилировался и не запускался. ZIP (zlib), сигнатуры, PE, лимиты, кэш и `--selftest` проверены на GCC 15.
- `CMakeLists.txt` не запускался (CMake в среде не было); сборку проверяли командой `g++`. При ошибке CMake используйте раздел «Без CMake».
- ZIP64 и методы сжатия, кроме stored/deflate, не поддерживаются: такие записи дают Skipped. Зашифрованные записи не проверяются.
- Только статический анализ: нет эмуляции, мониторинга в реальном времени, карантина и удаления. Проверяемые файлы не изменяются.
- PE: поддержаны PE32 и PE32+; ресурсы, сертификаты, .NET-метаданные и delay-импорты не разбираются.
- Файл, изменившийся во время сканирования, даст `Error`.
