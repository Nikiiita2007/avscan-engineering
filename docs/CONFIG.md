# Конфигурация avmonitor и формат событий

## Конфигурационный файл

```powershell
avmonitor.exe --config C:\AVScan\avmonitor.conf
```

Аргументы командной строки обрабатываются слева направо. `--config` загружает файл в той позиции, где указан, поэтому всё, что идёт после него, переопределяет значения из файла. Списки (`watch`, `exclude`, `priority`) накапливаются. Готовый пример: `config/avmonitor.example.conf`.

### Формат

- Строки вида `ключ = значение`. Регистр ключей и булевых значений не важен.
- Комментарии начинаются с `#` или `;` и занимают всю строку (в конце строки с значением комментарии не поддерживаются, чтобы `#` мог встречаться в путях).
- Значение можно взять в двойные кавычки (нужно для пробелов в краях). Экранирования нет: `D:\In\data` пишется как есть.
- Секция `[monitor]` необязательна; другие секции считаются ошибкой.
- Кодировка UTF-8 (BOM допускается).
- Неизвестный ключ, число вне диапазона или неверное значение останавливают запуск с сообщением `config line N: ...`. Опечатка не может молча остаться незамеченной.

### Ключи

| Ключ | Значение | Диапазон / по умолчанию |
|---|---|---|
| `watch` | каталог для наблюдения (повторяется) | если не задан, берутся `priority` |
| `exclude` | исключаемый каталог (повторяется) | |
| `priority` | каталог с повышенным приоритетом (повторяется) | |
| `db` | файл базы сигнатур | `db/signatures.db` |
| `quarantine` | каталог улик | `quarantine` |
| `threads` | число рабочих потоков | 1..32, по умолчанию 2 |
| `debounce_ms` | задержка после последнего события файла | 0..60000, по умолчанию 750 |
| `stable_ms` | время неизменности размера и даты перед сканом | 100..60000, по умолчанию 1000 |
| `max_size_mb` | файлы больше пропускаются | 1..1048576, по умолчанию 512 |
| `queue_limit` | размер очереди заданий | 1..10000000, по умолчанию 50000 |
| `etw` | включить ETW (нужны права администратора) | false |
| `block_exec` | завершать процесс при Infected | false |
| `auto_quarantine` | автоматически сохранять улику при Infected | false |
| `events` | формат вывода: `text` или `jsonl` | text |

### Служба Windows

Служба разбивает сохранённые аргументы по пробелам, поэтому путь к конфигу в `--install-service` и `--service-args` должен быть **без пробелов**: `--config C:\AVScan\avmonitor.conf`. Журнал службы по-прежнему пишется текстом в `%ProgramData%\AVScan\monitor.log`; ключ `events` на него не влияет.

## События JSON Lines (`--events jsonl`)

Каждая строка вывода — один компактный JSON-объект без повторяющихся ключей. Общие поля конверта:

- `v` — версия формата события (сейчас 1);
- `ts` — время UTC, `2026-11-13T14:39:37.123Z`;
- `event` — вид события: `scan`, `log`, `blocked` или `quarantined`.

Ключ конверта называется `event`, а не `type`, потому что у результата сканирования есть собственное поле `type` (тип файла: `pe`, `zip` и т. д.), и они не должны пересекаться.

`scan` содержит все поля результата сканирования (`path`, `status`, `message`, `size`, `type` файла, `sha256`, `score`, `detections`, `indicators`, `children` и т. д.; формат совпадает с `avscan --json`).

`log`, `blocked`, `quarantined` содержат `level` (`info`, `warning`, `error`) и `message` с исходной текстовой строкой монитора.

```json
{"v":1,"ts":"2026-11-13T14:39:37.123Z","event":"scan","path":"d:\\in\\a.txt","status":"Infected","type":"unknown","score":1000}
{"v":1,"ts":"2026-11-13T14:39:38.001Z","event":"log","level":"warning","message":"Warning: directory events lost; full rescan scheduled"}
```

Правила для потребителей: игнорируйте неизвестные поля; при изменении `v` формат может измениться несовместимо. Поток разбирается построчно (одна строка = один объект).

Примечание: пути в событиях `scan` приводятся к нижнему регистру, потому что монитор нормализует пути перед сканированием.
