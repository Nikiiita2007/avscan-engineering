# Архитектура Rust-экосистемы AVScan

## Компоненты
- `avscan-protocol` — кадры (4 байта длины little-endian + JSON, ≤ 1 MiB), конверт `Message`. Зеркалит `libs/host/protocol.hpp`.
- `avscan-manifest` — разбор и строгая валидация `module.json` (зеркалит `libs/host/manifest.hpp`).
- `orchestrator` — шина событий (`bus`), сессия протокола (`session`), supervisor (`supervisor`), конфиг; далее CLI и HTTP/SSE/WS (этап 6).
- `vuln-scanner` (id модуля `vuln_parser`), `net-analyzer`, `log-hunter` — отдельные процессы-модули.
- Антивирус остаётся на C++ (см. раздел «Транспорт»).

## Протокол (по `libs/host/module_host.hpp`)
Инициатор — **хост**:

1. хост → модуль `hello` (payload: `host_api`);
2. модуль → хост `hello_ack` (payload: `api_version`, `module_version`, `capabilities`; версии должны совпасть с манифестом, capabilities — подмножество манифеста);
3. хост → модуль `start` (payload: `config` = конфиг манифеста + переопределения);
4. модуль → хост `started`;
5. работа: модуль шлёт `event` (payload: `topic`, `data`), `log` (`message`), `error` (`message`); хост шлёт `ping` с `id`, модуль отвечает `pong` с тем же `id`;
6. хост → модуль `stop`, модуль отвечает `stopped`; при отсутствии ответа процесс убивается.

Все сообщения модуля несут `module` = id из манифеста. События с темами, не объявленными в `events.publishes`, отбрасываются. Любое нарушение (чужой `module`, неожиданный тип, неверный `pong`) завершает сессию ошибкой.

## Транспорт
C++ хост описывает транспорт абстрактно (на Windows — именованные каналы). Rust-оркестратор запускает модули как дочерние процессы и общается через stdin/stdout. Именованные каналы для C++ антивируса — отдельная задача (этап 6/7).

## Supervisor
На каждый модуль — своя задача: запуск процесса, handshake, цикл (события, ping при простое, остановка по сигналу). При ошибке и `restart.policy = on_failure` — перезапуск с экспоненциальной задержкой (`500 мс * 2^n`, максимум 30 с) не более `max_restarts` раз; иначе статус `Failed`. Логи — `tracing` + JSON.

## Конфигурация оркестратора
JSON-файл: список модулей (`manifest`, `binary`, `enabled`, `args`), адрес API (`listen`), каталог логов (`log_dir`). Все пути и порты настраиваются.

## Безопасность
Модуль не может публиковать темы вне объявленных. API по умолчанию слушает 127.0.0.1. Секреты в репозиторий не попадают; для push используется `gh auth` или `GH_TOKEN`.
